# คู่มือจัดการผู้ใช้ทีม (เพิ่ม / เปลี่ยนบทบาท / ปิดใช้งาน)

สำหรับหัวหน้า — ทำใน **Supabase Dashboard** (โปรเจกต์ `kprlqjxwolljkgqyzygf`) ทุกคำสั่ง SQL ใช้**อีเมล**ระบุตัวผู้ใช้ แค่เปลี่ยนค่าในเครื่องหมาย `'...'` แล้วกด Run

> ไม่ต้อง "สร้าง role" ใหม่ — ระบบมีบทบาทตายตัว 4 แบบ เลือกใช้อย่างใดอย่างหนึ่ง
> บัญชีเดียวใช้ได้ทั้งแอปจัดส่งเกาะและแอปเคลมสินค้า (ฐานข้อมูลเดียวกัน) แต่ละแอปเปิดให้ตามบทบาท

| role | ชื่อเรียก | เห็นเมนู |
|---|---|---|
| `packer` | คนแพ็ค | งานวันนี้ · นำเข้าออเดอร์ · หน้าแพ็ค · หน้าออเดอร์ |
| `pier` | คนท่าเรือ | งานวันนี้ · ตั้งค่าเรือวันนี้ · ที่ท่าเรือ · ลังโฟม · หน้าออเดอร์ |
| `manager` | หัวหน้า | ทุกเมนู + คิวเคลม · ยอดค้างชำระ · ผู้ลงทะเบียน LINE · ประวัติการใช้งาน · รายงานของขาด · ชื่อย่อลูกค้า · และแอปเคลมสินค้าทั้งหมด |
| `sale` | เซล (ผู้แจ้งเคลม) | **แอปเคลม:** แจ้งเคลมและดูเคลมของตัวเอง · **แอปเกาะ:** งานวันนี้ · หน้าออเดอร์ แบบ**อ่านอย่างเดียว** (ไม่มีปุ่มแพ็ค พิมพ์สติ๊กเกอร์ หรือแก้ข้อมูล) |

แอปเคลมเปิดให้เฉพาะ `sale` กับ `manager` · คนแพ็คและคนท่าเรือเข้าแอปเคลมไม่ได้

## 1. เพิ่มผู้ใช้ใหม่ (2 ขั้น)

**ขั้น 1 — สร้างบัญชี (ทำในหน้าเว็บ ใช้ SQL ไม่ได้)**

1. Supabase → **Authentication → Users → Add user → Create new user**
2. ใส่ **อีเมล** + **รหัสผ่านชั่วคราว**
3. ติ๊ก **Auto Confirm User** → กด Create

ระบบสร้างโปรไฟล์ให้เองเป็น `packer` แบบ**ยังไม่เปิดใช้งาน** (ล็อกอินได้แต่ไม่เห็นข้อมูลอะไร)

**ขั้น 2 — ตั้งชื่อ + บทบาท + เปิดใช้งาน** (Supabase → **SQL Editor** → New query)

```sql
update public.profiles p
set name      = 'ชื่อที่จะแสดงในแอป',
    role      = 'packer',          -- packer | pier | manager | sale
    is_active = true
from auth.users u
where u.id = p.id
  and u.email = 'อีเมลผู้ใช้@example.com';
```

- ขึ้น **UPDATE 1** = สำเร็จ
- ขึ้น **UPDATE 0** = อีเมลไม่ตรงกับที่สร้างในขั้น 1 (เช็คตัวสะกด / ตัวพิมพ์เล็ก)

**ขั้น 3 — แจ้งผู้ใช้**

- ส่งลิงก์แอป + อีเมล + รหัสผ่านชั่วคราวให้เจ้าตัว**โดยตรง** (ไม่โพสต์ในกลุ่ม)
- ล็อกอินครั้งแรก แอปบังคับตั้งยืนยันตัวตนสองชั้น (2FA) ด้วยแอป Authenticator บนมือถือ

## 2. ดูรายชื่อผู้ใช้ทั้งหมด

```sql
select u.email, p.name, p.role, p.is_active, u.last_sign_in_at
from public.profiles p
join auth.users u on u.id = p.id
order by p.is_active desc, p.role, p.name;
```

---

## 3. เปลี่ยนบทบาท

```sql
update public.profiles p
set role = 'pier'                  -- packer | pier | manager | sale
from auth.users u
where u.id = p.id
  and u.email = 'อีเมลผู้ใช้@example.com';
```

ผู้ใช้ต้อง**รีเฟรชหน้า / ล็อกอินใหม่**ถึงจะเห็นเมนูใหม่

---

## 4. ปิดใช้งาน (พนักงานออก / พักงาน)

> ห้ามกด **Delete user** — จะ error เพราะประวัติงาน (รูป เคลม ประวัติการใช้งาน) อ้างถึงคนนั้นอยู่ ให้**ปิดใช้งาน**แทน ข้อมูลเดิมยังอยู่ครบ

```sql
update public.profiles p
set is_active = false
from auth.users u
where u.id = p.id
  and u.email = 'อีเมลผู้ใช้@example.com';
```

แนะนำเพิ่ม: Supabase → **Authentication → Users** → เลือกคนนั้น → **Ban user** (กันล็อกอินด้วย)

**เปิดใช้งานกลับ:** รันคำสั่งเดียวกันแต่เปลี่ยนเป็น `is_active = true` (และ Unban ถ้าเคย Ban ไว้)

## 5. ปัญหาที่เจอบ่อย

| อาการ | วิธีแก้ |
|---|---|
| ล็อกอินได้ แต่หน้าว่าง / ไม่เห็นออเดอร์ | ยังไม่ได้เปิดใช้งาน → รันข้อ 1 ขั้น 2 (ต้องมี `is_active = true`) |
| ไม่เห็นเมนูที่ควรเห็น | บทบาทผิด → ข้อ 3 แล้วให้รีเฟรชหน้า |
| ลืมรหัสผ่าน | **Authentication → Users** → เลือกผู้ใช้ → **Send password recovery** (ส่งลิงก์ตั้งรหัสใหม่ทางอีเมล) |
| มือถือหาย / ลบแอป Authenticator → ติดหน้า 2FA | **Authentication → Users** → เลือกผู้ใช้ → ลบ **MFA factor** → ให้ล็อกอินใหม่แล้วตั้ง 2FA ใหม่ |
| UPDATE 0 | อีเมลไม่ตรง — รันข้อ 2 ดูอีเมลที่ถูกต้อง |
