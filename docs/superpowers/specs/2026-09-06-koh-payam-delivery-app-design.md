# สเปกการออกแบบ — แอปจัดการส่งสินค้าเกาะพยาม

วันที่: 2026-09-06
สถานะ: รอผู้ใช้รีวิว

---

## 1. บริบทและที่มา

- ผู้ใช้เป็นพนักงานแม็คโคร ทีมสาขา ทำหน้าที่จัดส่งสินค้าให้ลูกค้าบนเกาะพยามเป็นประจำทุกวัน
- แอปนี้เป็น **เครื่องมือของทีมสาขาที่ทำใช้เอง** ไม่ใช่โปรเจกต์ทางการของแม็คโคร
- ⚠️ **ต้องปรึกษาฝ่ายไอทีแม็คโครเรื่องการนำข้อมูลลูกค้าออกมาใช้ ก่อนใช้งานจริงกับข้อมูลจริง** — การออกแบบนี้เน้นปกป้องข้อมูลให้มากที่สุด แต่ไม่ได้แทนการขออนุมัติ
- ปริมาณงาน: ~60 ออเดอร์/วัน, ~300 ลัง/วัน
- ช่วงพีค: ตุลาคม–เมษายน ของทุกปี
- อุปกรณ์หน้างาน: มือถือ / แท็บเล็ต / คอมตั้งโต๊ะ
- สัญญาณเน็ตที่จุดแพ็ค: นิ่ง/แรงพอ — **ไม่ต้องรองรับออฟไลน์**
- การสั่งสินค้าของลูกค้าทำผ่านแอป/ระบบของแม็คโครอยู่แล้ว และ **export ออกมาเป็นไฟล์ CSV/Excel ต่อออเดอร์ได้**
- ลูกค้าชำระเงินกับแม็คโครโดยตรง — **แอปนี้ไม่เกี่ยวกับการรับชำระเงิน**

## 2. ปัญหาที่จะแก้ (เพนพ้อยรายวัน)

ปัจจุบันทุกอย่างประสานงานผ่าน LINE ทำให้จุกจิก ตกหล่น ตามย้อนหลังยาก โดยเฉพาะ 3 เรื่อง:

1. **สรุปการส่ง + ของขาดส่ง** — ต้องสรุปให้ลูกค้าแต่ละเจ้าว่าวันนี้ส่งอะไร กี่ลัง ขาดอะไร
2. **หลักฐานรูป** — ต้องถ่ายรูปจำนวนลัง (กระดาษ/โฟม) เก็บเป็นหลักฐาน และค้นย้อนหลังเวลามีปัญหา
3. **การเคลม** — ลูกค้าแจ้งของไม่ครบ/เสียหาย แล้วต้องตามตรวจและชดเชย

เรื่องประกอบอื่นที่เกี่ยวข้อง: การจัดของขึ้นเรือลำที่ 1/2/3 (ตัดสินที่ท่าเรือ), การสรุปยอดของขาด/เคลมเป็นตัวเงิน (เพื่อไปทำเรื่องคืนเงินในระบบแม็คโครต่อ), การเขียนชื่ออังกฤษหน้าลัง

## 3. เป้าหมาย

เว็บแอปที่แทนการประสานงานผ่าน LINE แบบจุกจิก ให้ข้อมูลการส่งของแต่ละออเดอร์อยู่ที่เดียว ทีมอัปเดตพร้อมกันได้ ลูกค้าเปิดดูสถานะและแจ้งเคลมได้เองผ่านลิงก์

## 4. ผู้ใช้และสิทธิ์การเข้าถึง

### ฝั่งทีม (ภาษาไทย)
- ต้องล็อกอิน + เปิดยืนยันตัวตน 2 ชั้น (2FA)
- แบ่งบทบาท: **คนแพ็ค** / **คนที่ท่าเรือ** / **หัวหน้า**
- ใช้งานพร้อมกันหลายคนได้ เห็นการอัปเดตของกันแบบเรียลไทม์

### ฝั่งลูกค้า (อังกฤษเป็นหลัก + สลับไทยได้, ค่าเริ่มต้นอังกฤษ)
- **ไม่ต้องล็อกอิน**
- เข้าได้ 2 ทาง:
  - ลิงก์เฉพาะที่มี token สุ่มยาว เดาไม่ได้ (ทีมก๊อบไปวางให้ทาง LINE)
  - กรอกเลขที่คำสั่งซื้อ + รหัสยืนยัน 4 หลัก (แอปสร้างให้ แสดงในหน้ารายละเอียดออเดอร์ฝั่งทีม)
- เห็นเฉพาะออเดอร์ของตัวเองเท่านั้น
- ลิงก์/สิทธิ์เข้าถึงหมดอายุเมื่อพ้นเดดไลน์เคลม

## 5. ขอบเขตเฟส 1

1. **นำเข้าออเดอร์** — อัปโหลดไฟล์ export จากแม็คโคร (CSV/Excel) → ระบบอ่านและแสดงตัวอย่าง → ยืนยันเพื่อสร้างออเดอร์ + รายการสินค้าของวันนั้น (มีการกันนำเข้าซ้ำ)
2. **หน้าแพ็ค (รายออเดอร์)** — เช็กลิสต์รายการสินค้า, มาร์ก "ของขาด (หมดสต็อก)" รายบรรทัด, กรอกจำนวนลังกระดาษ + ลังโฟม, ปุ่ม "แพ็คเสร็จ", แสดงยอดมูลค่าของขาดที่คำนวณได้
3. **ใบสรุปสำหรับเขียนหน้าลัง** — แสดง/ปรินต์ต่อออเดอร์: ชื่ออังกฤษตัวใหญ่ + จำนวนลัง (เช่น เขียน 1/5 ถึง 5/5) เพื่อให้ทีมเขียนหน้าลังด้วยปากกาเคมีเหมือนเดิม (ไม่ใช้สติกเกอร์ติดลัง — เสี่ยงหลุดบนลังโฟม/บนเรือ)
4. **หน้าท่าเรือ (บนมือถือ เน้นเร็ว)** — ค้น/เลือกออเดอร์ → เลือกเรือลำที่ 1/2/3 (ทั้งออเดอร์ไปลำเดียวกัน) → ถ่ายรูปหลักฐานจำนวนลัง → ปุ่ม "ส่งที่ท่าเรือแล้ว"
5. **แดชบอร์ดรายวัน** — ออเดอร์ทั้งหมดของวัน พร้อมสถานะและความคืบหน้า (แพ็คแล้ว X/60, ถึงท่าเรือ Y, ส่งแล้ว Z) ค้น/กรองได้
6. **หน้าลูกค้า** — ไทม์ไลน์สถานะ, รายการสินค้า + จำนวน, รายการ "ของขาด – ไม่ได้ส่ง" ที่ชัดเจน, จำนวนลัง (กระดาษ/โฟม), เรือลำที่, รูปหลักฐาน, สรุปเครดิต, ปุ่มแจ้งเคลม
7. **เคลม** — ลูกค้ากดแจ้งเคลมรายรายการ (ของในลังไม่ครบ / เสียหาย / ลังหาย) ภายใน **48 ชั่วโมง** หลังออเดอร์ถูกตั้งสถานะ "ส่งที่ท่าเรือแล้ว" → เข้าคิวให้ทีม → ทีมอนุมัติ/ปฏิเสธ + เลือกวิธีชดเชย (คืนเงินพร้อมระบุจำนวน / ส่งชดเชยวันถัดไป) + ใส่โน้ต
8. **สรุปเครดิตต่อออเดอร์ (คำนวณ)** — มูลค่าออเดอร์ − มูลค่าของขาด − เคลมที่อนุมัติแบบคืนเงิน = ยอดสุทธิ + รายการ "ค้างส่งวันถัดไป"; แอปเป็นแค่บันทึก/แจ้งให้ทราบ ทีมนำไปทำเรื่องคืนเงินในระบบแม็คโครจริงเอง
9. **หน้ารายละเอียดออเดอร์ (ฝั่งทีม)** — ประวัติทั้งหมด, รูปทุกใบ, เคลมทุกอัน, สรุปเครดิต, รหัสยืนยันลูกค้า, ปุ่มก๊อบลิงก์ลูกค้า
10. **คิวเคลม (ฝั่งทีม)** — เคลมที่เปิดอยู่ทั้งหมด กรองตามสถานะ/ใกล้เดดไลน์ → เปิดดูคำแจ้ง+รูปลูกค้า เทียบกับรูปหลักฐานเรา + รายการออเดอร์
11. **บันทึกการใช้งาน (Audit log) แบบพื้นฐาน** — ใครทำอะไรเมื่อไหร่

## 6. เลื่อนไปเฟส 2 (ไม่ทำตอนนี้)

- LINE Official Account + แจ้งเตือนอัตโนมัติ (push) — เฟส 1 ทีมก๊อบลิงก์ส่งใน LINE เอง
- ใบรายการสินค้ากระดาษ A5 ใส่ไว้ในลัง (ช่วยลูกค้าเช็กของ + เป็นหลักฐานเคลม)
- ปรินต์ใบสรุปทั้งวันรวดเดียว (เฟส 1 ทำทีละออเดอร์)
- รายงาน/แดชบอร์ดสถิติ
- เชื่อมระบบบัญชี / ออกใบลดหนี้
- แอปติดตั้งบนมือถือ (เฟส 1 เป็นเว็บ เพิ่มลงจอโฮมได้)
- จัดการสต็อกสินค้า
- สรุปยอดรวมหลายออเดอร์ / ยอดยกมา

## 7. โครงข้อมูล

| เอนทิตี | ฟิลด์หลัก |
|---|---|
| **ShipDay** (รอบจัดส่งรายวัน) | วันที่, สถานะรวม |
| **Order** (ออเดอร์) | เลขที่คำสั่งซื้อ (แม็คโคร), ชื่ออังกฤษลูกค้า, วันจัดส่ง, สถานะ, token ลิงก์ลูกค้า, รหัสยืนยัน 4 หลัก, เรือลำที่ (1/2/3, ใส่ที่ท่าเรือ), มูลค่ารวม (คำนวณ) |
| **OrderItem** (รายการสินค้า) | order, ชื่อสินค้า, จำนวนที่สั่ง, ราคาต่อหน่วย, มูลค่ารายการ, สถานะ (ปกติ/ของขาด), จำนวนที่ส่งจริง |
| **Box** (ลัง) | order, ชนิด (กระดาษ/โฟม), เลขลัง n จาก N — ระบบสร้าง 1..N จากจำนวนที่ทีมกรอก |
| **EvidencePhoto** (รูปหลักฐาน) | order, ไฟล์รูป (เก็บบน R2), เวลาถ่าย, ใครถ่าย, โน้ต |
| **Claim** (เคลม) | order, (อ้าง OrderItem/Box ถ้าระบุได้), ประเภท, จำนวน, คำอธิบาย, รูปจากลูกค้า, เวลาแจ้ง, เดดไลน์, สถานะ (เปิด/อนุมัติ/ปฏิเสธ/ปิด), วิธีชดเชย (คืนเงิน+จำนวน / ส่งชดเชยวันถัดไป), ใครเคลียร์, เมื่อไหร่ |
| **User** (ผู้ใช้ทีม) | ชื่อ, อีเมล, บทบาท (คนแพ็ค/คนท่าเรือ/หัวหน้า), 2FA |
| **AuditLog** | ผู้ใช้, การกระทำ, เอนทิตีที่เกี่ยวข้อง, เวลา |
| **สรุปเครดิต** | คำนวณจาก Order + OrderItem + Claim ไม่เก็บแยก |

สถานะออเดอร์: `นำเข้าแล้ว → กำลังแพ็ค → แพ็คเสร็จ → ถึงท่าเรือ → ส่งที่ท่าเรือแล้ว` (สถานะสุดท้าย ไม่มีขั้นยืนยันรับของ)

## 8. กติกาสำคัญ

- **เดดไลน์เคลม:** 48 ชั่วโมง นับจากเวลาที่ออเดอร์ถูกตั้งสถานะ "ส่งที่ท่าเรือแล้ว" พ้นแล้วปุ่มแจ้งเคลมปิด
- **ของขาด (หมดสต็อก):** มาร์กรายบรรทัด → หักมูลค่ารายการนั้นออกจากยอด → ทีมไปทำเรื่องคืนเงินในระบบแม็คโครต่อ (แอปแค่บันทึก/แจ้ง)
- **ทั้งออเดอร์ขึ้นเรือลำเดียวกัน** — เลือกเรือทีเดียวจบที่ระดับออเดอร์
- **ลบข้อมูลอัตโนมัติ:** ออเดอร์ + รายการ + รูป + เคลม ที่เกิน **30 วัน** ถูกลบทิ้ง
- **รูป:** บีบขนาดในเบราว์เซอร์ให้เหลือ ~150–200KB, สูงสุด 3 รูป/ออเดอร์

## 9. การออกแบบให้ข้อมูลปลอดภัย

**เก็บเฉพาะที่จำเป็น:**

| ข้อมูล | เก็บ | หมายเหตุ |
|---|---|---|
| เลขที่คำสั่งซื้อ | ✅ | อ้างอิง + ให้ลูกค้าค้นหา |
| ชื่อภาษาอังกฤษลูกค้า | ✅ | ใช้เขียนหน้าลัง |
| รายการสินค้า + จำนวน | ✅ | หัวใจของการสรุป |
| ราคาต่อรายการ | ✅ | คำนวณยอดของขาด/เคลมอัตโนมัติ |
| ที่อยู่ / เบอร์ / อีเมลลูกค้า | ❌ | ไม่จำเป็น — ส่งถึงท่าเรือ ไม่ใช่ถึงบ้าน |

**มาตรการ:**
- ลิงก์ลูกค้าเป็น token สุ่มยาวเดาไม่ได้ + หมดอายุเมื่อพ้นเดดไลน์เคลม
- ทางค้นด้วยเลขออเดอร์ต้องใส่รหัสยืนยันคู่กัน + จำกัดจำนวนครั้งที่ลองผิด (rate limit)
- ตรวจ token/รหัสยืนยันผ่าน Edge Function ไม่เปิดตารางให้เข้าถึงตรง (Row Level Security เข้มงวด)
- บัญชีทีมล็อกอิน + 2FA, แบ่งสิทธิ์ตามบทบาท
- เข้ารหัสข้อมูลทั้งตอนส่งและตอนเก็บ, เลือก region สิงคโปร์
- ห้าม export ข้อมูลกองใหญ่จากแอป ยกเว้นหัวหน้า + มี audit log
- ลบข้อมูลอัตโนมัติที่ 30 วัน

## 11. การส่งมอบ

- โค้ดอยู่ใน GitHub ของผู้ใช้, บัญชี Supabase / Vercel / Cloudflare เป็นของผู้ใช้

## 13. สิ่งที่ต้องขอจากผู้ใช้ก่อนเริ่ม

1. ไฟล์ตัวอย่าง export จากแอปแม็คโครจริง 1 ไฟล์ (ปิดข้อมูลอ่อนไหวได้) — เพื่อ map คอลัมน์
2. รายชื่อสมาชิกทีม + บทบาท + อีเมล

## 14. ประเด็นที่ยังต้องยืนยันตอนรีวิวสเปก

- **หน้าทีมเป็นภาษาไทย, หน้าลูกค้าอังกฤษเป็นหลัก + สลับไทย** — สมมติไว้แบบนี้ ยืนยันด้วย
- **เรือมี 3 ลำเสมอ (1/2/3)** หรือบางวันมากกว่า/น้อยกว่า/มีชื่อเรือ?
- **ลูกค้า 1 เจ้า มีได้หลายออเดอร์ต่อวันไหม** — กระทบการค้นหาและการแสดงผล
- **การนำเข้าซ้ำ/ออเดอร์ที่ถูกแก้แล้ว export ใหม่** — ให้ทับของเดิม หรือเตือนก่อน?
- **รหัสยืนยัน 4 หลัก** — ให้แอปสุ่มสร้างแล้วทีมแจ้งลูกค้า (ตามที่ออกแบบไว้) โอเคไหม
- **การชดเชยแบบ "ส่งวันถัดไป"** — ระบบควรสร้างรายการค้างส่งในออเดอร์วันถัดไปให้อัตโนมัติ หรือแค่บันทึกโน้ตไว้เฉย ๆ ในเฟส 1?
